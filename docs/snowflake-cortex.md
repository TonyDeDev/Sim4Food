# Snowflake Cortex order assistant

The Forecast tab has two AI features, both generated by Snowflake Cortex:

- **This week in plain words**: a 3 to 5 sentence summary of the latest forecast run and order.
- **Ask about this order**: a chat box that streams answers to the owner's questions about that run.

The forecast and the order quantities never depend on the LLM.
Cortex only explains numbers the model already produced, so the app works the same without it.

## How it works

```
Forecast tab -> POST /api/insights/summary | /api/insights/chat   (FastAPI, same session auth)
  -> latest stored forecast run (simulation_runs)
  -> compact JSON context (build_context in backend/app/insights.py)
  -> Snowflake Cortex REST: POST https://<account>.snowflakecomputing.com/api/v2/cortex/v1/chat/completions
  -> summary text (cached per run) | streamed text deltas
```

| File | Role |
|---|---|
| `backend/app/cortex.py` | REST client: PAT auth, OpenAI-style body, SSE streaming, readable errors. |
| `backend/app/insights.py` | Routes `/api/insights/status`, `/summary`, `/chat`, the prompts and the context builder. |
| `src/components/ForecastSummary.jsx` | Summary card with a "Rewrite" button. |
| `src/components/ForecastChat.jsx` | Chat panel with suggested questions, streamed answers. |

### Grounding and safety

- The context is built only from the latest stored forecast run: target week, accuracy, delivery days, savings, order backtest, events, and per ingredient the likely range, order per delivery, stock, run-out risk and expected waste.
- The system prompt tells the model to answer only from that context, to say when data is missing, and never to invent numbers.
- The context is labelled as data, not instructions, and owner text only ever goes in `user` messages.
- Chat history is trimmed to the last 10 turns, 2000 characters each, and must end with the owner's message.
- Em dashes are replaced with plain hyphens on the way out (house style).
- Every route uses the same session cookie and restaurant ownership check as the rest of the API.

## Snowflake setup

These steps are done once in Snowsight by an account admin.

1. **Role with Cortex access.**
   The user whose token the app uses needs a default role with `SNOWFLAKE.CORTEX_USER` (or the narrower `SNOWFLAKE.CORTEX_REST_API_USER`):

   ```sql
   CREATE ROLE IF NOT EXISTS swarmstock_ai;
   GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE swarmstock_ai;
   GRANT ROLE swarmstock_ai TO USER <your_user>;
   ALTER USER <your_user> SET DEFAULT_ROLE = swarmstock_ai;
   ```

2. **Programmatic access token (PAT).**
   In Snowsight open the user menu, then Settings, then Authentication, and generate a programmatic access token for that role.
   By default Snowflake only accepts a PAT from a user covered by a network policy.
   For a hackathon, either add a network policy that allows the backend's IP, or ask the admin to relax the PAT network policy requirement for this user.

3. **Model availability.**
   The default model is `claude-sonnet-4-5`.
   If the account's region does not host it, enable cross-region inference:

   ```sql
   ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';
   ```

   Or set `CORTEX_MODEL` to a model available in the region (for example `llama3.1-70b` or `mistral-large2`).
   The Cortex Playground in Snowsight is a quick way to check which models the account can call.

## App configuration

In `backend/.env` (never commit it):

```
SNOWFLAKE_ACCOUNT=guvzzec-ss98777
SNOWFLAKE_PAT=<programmatic access token>
CORTEX_MODEL=claude-sonnet-4-5
```

- `SNOWFLAKE_ACCOUNT` is `<org>-<account>`: the Snowsight URL `app.snowflake.com/guvzzec/ss98777/` gives `guvzzec-ss98777`.
  Underscores are turned into hyphens automatically, as Snowflake URLs require.
- Without `SNOWFLAKE_ACCOUNT` and `SNOWFLAKE_PAT` the routes return 503 and the Forecast tab shows "The AI assistant (Snowflake Cortex) is not set up on this server yet."

## Errors the owner can see

| Cortex response | Message |
|---|---|
| 401 | The access token was rejected (wrong or expired PAT, or a network policy blocks this server). |
| 403 | The user's default role cannot use Cortex; grant `SNOWFLAKE.CORTEX_USER`. |
| 400 about the model | The model is not available in this region; enable cross-region or change `CORTEX_MODEL`. |
| 429 | Rate limited; try again. |
| No forecast run yet | 409: "Run a forecast first, then ask about it." |

## Testing

`backend/tests/test_insights.py` covers the request shape and account URL, streaming, error messages, the context builder, history trimming, the 503 without configuration, summary caching and chat streaming, all with `httpx.MockTransport` (no network).

A live check needs a real PAT in `backend/.env`: run a forecast, then open the Forecast tab and ask a question.
